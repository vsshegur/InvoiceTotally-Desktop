# Vipul Workplace 3.8.0 — Accounting Workflow Release

## Included
- **Bank reconciliation:** Compare imported bank statements to the live Tally ledger and review any ambiguous matches. The app does not set Tally BRS dates.
- **Smart Bank Accounting:** Explicitly assign existing Tally ledgers to unposted bank rows. Approved narration keys can be remembered as suggestions, never silently posted. Party ledger payments/receipts require deliberate **On Account** approval.
- **Meesho / Flipkart settlement preview:** Map columns in actual payout Excel reports, review deductions and net payout, then compare against imported bank statement credits. No Journal or settlement-adjustment voucher is created automatically.
- **Accounting Action Center:** Unified exceptions, including bank and GST issues, marketplace settlement differences, invoice reviews and failed Tally jobs.
- **Inter-company reconciliation:** Compare reciprocal ledger vouchers in two open Tally companies for a chosen month, with exact reference and opposite-sign evidence. Read-only.
- **Startup diagnostics and recovery:** Local database integrity checks, pre-upgrade SQLite backup, transactional schema setup, and visible errors instead of indefinite loading.

## Removed modules
**Outstandings, GST Invoice Links and Posting Audit** are removed from screens, routes, implementation and new SQLite schema definitions. This does not remove ordinary GSTR-2B reconciliation or the core GST upload/posting flows. The separate audit hash-chain is gone; normal Tally job outcomes remain in the Tally log.

Existing local SQLite databases are **not destructively cleaned** during updates. Tables and previous data from older versions, if present, remain untouched in the local file. Do not manually delete that file.

## Safety
- No reconciliation screen changes existing Tally vouchers or marks Tally BRS reconciliation dates.
- The normal create-only voucher validator, explicit post approval and external duplicate checks remain.
- An uncertain bank posting requires manual review against live Tally before it can be considered for another attempt.
- Only existing Tally ledger masters can be assigned, with company-specific authorization.
- Accounting interpretations of settlement fees, TCS/TDS, refunds and GST must be checked with representative records before production.

## Install / validation
1. Before upgrading, create a verified and preferably encrypted backup from the app and store a copy off the PC.
2. Use a separate Tally **test company** first to validate the new bank and settlement workflows, company routing and voucher results.
3. Install the versioned 3.8.0 Windows Setup EXE generated by the successful `main` workflow. The installer retains `%LOCALAPPDATA%\InvoiceTotally` user data.
4. Check the imported Tally master list, one real bank statement and representative marketplace settlement exports.
5. For rollback, reinstall the previously known-good installer and restore the matching pre-upgrade SQLite backup. Never assume an older executable supports a newer database schema.

A clean automated Windows startup/build and unit-test suite are required for release. Mock data cannot guarantee live Tally, bank and marketplace correctness.
